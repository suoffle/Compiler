### __2. 구현 내용__
#1 선언문의 명칭과 나칩 분석 및 재귀적인 타입 탐색으로 크기 계산
#2 변수나 파라미터: 타입에 따라 크기를 계산하여 activation record(스택 프레임)에 위치할 주소 계산
#3 함수:
- 리턴 타입 분석
- parameter list의 내용이 올바른 타입인지 검사 / 크기와 주소 계산
- 함수의 body에 선언된 지역 변수의 크기 계산
#4 수식: 연산자 및 피연산자 타입과 규칙 검사 
#5 전체적인 명령문과 수식이 정당한지 분석
#6 프로그램의 모든 상수를 수집해서 literal로 저장
#7 타입의 호환성: C언어의 타입에 따라 호환적인 타입의 타입 변환 및 연산 구현(명시적, 묵시적 방법)
#8 단항 연산자
- 문자 type: 정수 타입으로 변환
- 배열 type: 동일한 type의 포인터 타입으로 변환
- 함수 type: 같은 함수형 포인터 타입으로 변환   

<br>```
<참고>
lvalue: 메모리에서 주소를 가지는 값으로 수식의 왼쪽과 오른쪽 모두 올 수 있다. 즉, lvalue 수식은 대입 연산의 좌측에 나올 수 있다.

### __3. 발생한 오류 및 해결 방법__
- getPointerFieldIdentifier, set_expression 함수에서 닫는 괄호를 놓쳐 오류가 발생하였다.(오타)    <br>
  - 해결 방법: 적절한 위치에 닫는 괄호를 추가하였다.  
- sem_arg_expr_list에서 llink가 아닌 link를 적어 오류가 발생하였다.(오타)    <br>
  - 해결 방법: 오타를 수정하였다.  
- N_EXP_ARRAY에서 t가 usual_binary_conversion 할 때 t가 선언되지 않고 처음 사용되어서 오류가 발생하였다.    <br>
  - 해결 방법: 해당 페이지에 A_TYPE *t를 통해 선언을 했다.  
- main 함수에서 semantic_err를 찾을 수 없다는 error가 발생하였다.    
  - 해결 방법: extern 선언을 해서 외부에서 해당 값을 가져올 수 있게 하였다.  
- sem_func.c와 func.c에 isPointerOrArrayType 함수가 중복 선언되어 오류가 발생하였다.     
  - 해결 방법: semfunc.c에 있는 함수를 주석처리 하였다.  
<br>
